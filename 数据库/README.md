# 三年报告元数据入库工具

本目录实现三年报告的首期元数据入库。工具递归发现 2023/2024/2025 PDF，严格解析文件名，生成 CSV/JSON manifest，并在事务中幂等写入 SQLite。它只检查文件系统元数据、`%PDF-` 文件头和 `%%EOF` 文件尾，**不解析 PDF 正文、页表或 OCR**。

## 运行

```powershell
python .\构建三年报告清单.py `
  --报告根目录 "<ESG报告原件目录>" `
  --priority-200 "<优先200家公司清单.csv>" `
  --SQLite输出 ".\三年报告元数据.sqlite" `
  --manifest-csv ".\三年报告清单.csv" `
  --manifest-json ".\三年报告清单.json" `
  --哈希范围 p531 `
  --根目录代码 "SSE_ESG_2023_2025"
```

默认不计算 PDF SHA-256，清单的 `sha256` 为空，适合快速审计。正式冻结可用 `--哈希范围 p200`、`--哈希范围 p531` 或 `--哈希范围 all`；旧参数 `--计算哈希` 等价于 `all`。哈希以 1 MiB 分块流式计算，不改写源文件。

脚本支持同义英文参数：`--report-root`、`--sqlite-output`、`--compute-hash`、`--root-code`。SQLite 结构来自同目录 `数据库结构.sql`。

## 数据口径

- 公司键固定为 `SSE + 6 位股票代码`，文件名简称按年度进入 `company_alias`。
- 多标签保留原始标签块，并按 `CSR,ENV,ESG,SD,OTHER` 生成可逆 `report_type_key`。
- `report` 与 `report_version` 分表；同一逻辑键的不同文件不会互相覆盖。
- P200 快照保存优先公司及其 2025 当前版本；P177 保存三年槽位均为 `present` 的公司；P531 锁定 P177 的三年报告版本。
- priority CSV 中每家公司预建 2023—2025 三个槽位。正式 200 家数据应对账为 600 槽位，其中 571 `present`、29 `missing_not_found`，P177/P531 应为 177/531。
- 每次运行自动执行两遍事务合并，第二遍任何表新增记录都视为失败；两遍均检查 `foreign_key_check` 和 `integrity_check`。
- 数据库只保存 `root://<根目录代码>` 和相对路径，不写入开发机器的盘符、用户名或绝对目录。
- `P531` 完成 SHA-256 只证明文件内容身份已冻结，不代表 531 份报告均已完成正文指标抽取。

## 已验证产物

匿名公开快照在上级 `正式数据产物` 目录提供：

- `平台公开演示数据库.sqlite`
- `P531哈希与幂等性验证结果.json`

完整三年清单 CSV/JSON 与元数据哈希库体积较大，未在匿名公开快照中重复分发。公开演示数据库保留3,880份报告元数据、P177/P531快照成员关系和固定15份演示结果；冻结计数、哈希范围、幂等结果与事实边界以随仓库提供的验证结果 JSON 为准。

真实运行共发现 3880 份报告；其中 P531 为 177 家公司连续三年的 531 份报告，已计算 SHA-256。数据库完整性检查为 `ok`，外键错误数为 0，同进程二次导入和跨进程重跑均无新增实体。具体数值与事实边界以验证结果 JSON 为准。
